# 资产管理系统 (Asset Management System)

基于 Django 的企业级固定资产管理系统，覆盖资产台账、领用归还、变更记录、组织架构与基于角色的权限控制（RBAC），支持 Excel 批量导入与 CSV 导出，可局域网内多用户访问。

## 功能特性

### 📊 数据总览
- 资产总数、总价值、在用/库存数量一目了然
- 领用中、逾期未还统计（逾期由归还日期动态推导，口径统一）

### 🗃️ 资产库
- 资产台账：编号、名称、类别、规格、配置、序列号、价值、存放位置等
- **双模式搜索**：单输入框 + 一键切换 —— 默认按「资产编号/名称」搜，点击按钮切换为按「责任人/实际使用人」搜
- 组合筛选：状态 / 类别 / 部门，支持排序、分页（每页 10/20/50/100 条）
- 单条新增/编辑/删除、勾选批量删除（有领用/变更历史的资产受级联保护，禁止误删）
- Excel 批量导入（提供模板下载，导入失败整批回滚）；按当前筛选条件导出 CSV

### 🏢 组织架构
- 部门树状结构（支持上下级），负责人与描述
- 名下有资产的部门禁止删除，防止资产失去所属

### 📤 资产领用
- 领用 / 归还流程：借出时资产状态自动置为「借出」，全部归还后自动回「库存」
- 状态只有「借出 / 已归还」两态，「逾期」由预计归还日期动态推导，不产生脏数据
- 全流程事务保护，状态同步原子完成
- 按当前筛选（全部/借出/已归还/逾期）一键导出 Excel

### 🔄 资产变更
- 部门转移 / 状态变更两类变更记录，完整保留变更前后值与经办人
- 校验严格：目标部门必须真实存在（杜绝误建部门）、状态必须合法
- 按当前筛选（全部/部门转移/状态变更）一键导出 Excel

### 👥 用户与权限
- 基于「角色」的权限模型（RBAC）：按模块分配查看/管理权限（资产库、组织架构、领用、变更、用户管理）
- 登录安全：密码连续输错 5 次锁定 5 分钟；除超级管理员外，同一账号同一时间仅允许一台设备在线（新登录自动将旧设备踢下线）
- 内置账号保护：初始超管 admin（admin123）不可删除、停用或降级；密码仅首次部署设置，日常启动不重置
- 新增/编辑用户独立校验（用户名/密码/角色必填），**密码需通过 Django 密码校验器**（长度、纯数字、常见弱口令、与用户名相似度）
- **内置超管保护**：`admin` 账号在用户列表中带「内置」标识，不可删除、不可停用、不可降级，从页面和 Django 后台两条路径都做了拦截
- 右上角优先显示用户姓名，无姓名时回退用户名

### 💾 数据备份（Django admin）
- 入口：侧栏「后台管理」→ 应用列表中的「数据备份」
- **一键手动备份**：以 SQLite 在线备份 API 生成整库一致性快照，包含资产 / 部门 / 领用 / 变更 / 用户 / 角色全部数据，存入项目根 `backup/` 文件夹
- **自动备份**：可开关；频率支持「每 1 天 / 每 3 天 / 每 7 天 / 每次数据库变动」
- 备份文件名以日期为主（同日多次追加时间）；`backup/` 内超过 9 份自动删除最旧的
- 备份列表支持**下载**（下载时可另存到任意位置）、**恢复**（恢复前自动另存当前库并二次确认）、删除

## 快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 启动（Windows 双击 start.bat，或命令行）
python manage.py migrate
python ensure_admin.py
python manage.py runserver 0.0.0.0:12036
```

- 浏览器访问 `http://127.0.0.1:12036/`
- 默认管理员：**admin / admin123**（首次登录后请立即修改密码）
  - `admin` 是**系统内置超管账号**，首次部署时随初始化写入数据库，**不可删除、不可停用、不可降级**，用于避免系统被锁死；
  - 该密码**只在首次创建时设置一次**，之后每次启动都不会再改动——你改过的密码会一直有效。

### 使用演示数据

仓库附带一套纯虚构演示数据库 `db.demo.sqlite3`（12 个部门、37 项资产、3 条领用、2 条变更，与任何真实数据无关）：

- `USE_DEMO_DATA.bat` —— 项目根目录没有 `db.sqlite3` 时，把演示库复制为默认库（已存在真实库则不覆盖）
- `build_demo_db.bat` —— 重新生成全新演示库

### 导入真实数据

**方式一：脚本直接导入（推荐，一条命令）**

1. 把原始 Excel 放到 `实际数据/迈德固定资产在线表.xlsx`
2. 双击 `import_data.bat`，或命令行 `python import_real_data.py`
3. 导入为**幂等增量同步**：已存在的资产更新，不存在的新增，不清空历史业务记录

**方式二：改成模板后从页面导入**

原始在线导出表有 30 列、表头在第 3 行，字段名与页面模板不一致，直接上传无法识别。
用转换脚本先「翻译」成页面模板的 13 列：

```bash
python convert_to_template.py                     # 默认：实际数据/迈德固定资产在线表.xlsx → 实际数据/导入模板_资产数据.xlsx
python convert_to_template.py --fill-user         # 实际使用人为空/「无」时用责任人填充
python convert_to_template.py --create-departments # 顺便把缺失的部门写入数据库
```

转换后打开「资产库 → ⬆ 导入Excel」，上传 `实际数据/导入模板_资产数据.xlsx` 即可。
脚本会同时打印报告：类别/状态归一化条数、必填项缺失被跳过的行、数据库中不存在的部门等。

> 页面导入要求「所属部门」已存在于组织架构、「责任人/实际使用人/存放位置」非空，
> 否则该行会被跳过。原始表里常有一批「实际使用人」为空的行，用 `--fill-user` 可自动补上。

**类别 / 状态自动归一化**：外部台账里的常见写法会自动映射到系统标准值，无需手工清洗。

| Excel 原值 | 归一化为 |
|---|---|
| 笔记本 / 笔记本电脑 | 笔记本电脑 |
| 台式机 / 台式电脑 / 台式机电脑 | 台式机电脑 |
| 交换机 / 路由器 / 服务器 | 网络设备 |
| 显示器 / 电脑 | 电脑 |
| 打印机 | 办公电器 |
| 闲置 / 借用 / 员工离职 | 库存 |
| 待报废 | 报废 |
| 待维修 / 报修 | 维修 |

> 系统标准类别：笔记本电脑、台式机电脑、电脑、办公家具、网络设备、软件、办公电器、其他。
> 映射表定义在 `assets/models.py` 的 `Asset.CATEGORY_ALIAS` / `Asset.STATUS_ALIAS`，页面导入与脚本导入共用同一份。

## 局域网访问

服务器默认绑定 `0.0.0.0:12036`，局域网内同事通过 `http://<服务器局域网IP>:12036/` 访问。若无法访问，请检查：

1. Windows 防火墙是否放行 TCP 12036 入站
2. 各设备是否在同一网段

> ⚠️ 本项目使用 Django 开发服务器，适合小团队内部使用；正式生产环境请改用 Gunicorn/uWSGI + Nginx 等生产级部署，并更换 `SECRET_KEY`、关闭 `DEBUG`。

## 数据模型

- **Asset** 资产台账：编号（唯一）、名称、类别、规格、配置、责任人、实际使用人、所属部门、状态（在用/库存/借出/维修/报废）、价值、购置日期、存放位置
- **Requisition** 领用记录：资产、领用人、领用部门、用途、领用/预计归还/归还日期、状态（借出/已归还，逾期动态推导）
- **AssetChange** 变更记录：资产、变更类型（部门转移/状态变更）、变更前后值、经办人、原因
- **Department** 部门：树状上下级、负责人
- **Role / UserProfile** 角色与用户档案：细粒度布尔权限位
- **BackupSetting** 备份设置（单例）：自动备份开关、频率、备份目录、上次备份时间

## 部署与安全

### 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `ASSETS_SECRET_KEY` | 内置开发默认值 | 部署前请替换为随机字符串 |
| `ASSETS_DEBUG` | 关闭 | 排查问题时设为 `1` 临时开启 |
| `ASSETS_ALLOWED_HOSTS` | `*`（不限制） | 收紧时填 `192.168.1.10,asset.local` 形式 |
| `ASSETS_DB_PATH` | `db.sqlite3` | 指定其它数据库文件（演示库 / 测试库） |

> 调试模式默认关闭，错误页不会把源码与 SQL 暴露给局域网访问者。
> 由于 DEBUG 默认关闭，`start.bat` 使用 `runserver --insecure` 以便继续提供静态文件。

### 已加固项

- **内置超管保护**：`admin` 不可删除 / 停用 / 降级，页面与 Django 后台双重拦截
- **密码强度校验**：修改密码、新增用户、重置密码均走 Django 密码校验器
- **启动脚本不再重置密码**：`ensure_admin.py` 完全幂等，内置角色的权限也不会被覆盖
- **XSS 防护**：消息 Toast 改用 `json_script` 输出；可搜索下拉改用 DOM 文本节点而非 `innerHTML`；删除确认文案改由 `data-confirm` 属性传递（由模板自动转义）
- **后台入口收敛**：侧栏「后台管理」仅对 staff / superuser 显示

### 数据与仓库

- 仓库不包含任何真实业务数据：`db.sqlite3` 与 `实际数据/` 已被 `.gitignore` 排除，演示库为纯虚构数据
