# 部署指南（Linux + Docker / 1Panel）

把资产管理系统部署到 Linux 服务器（配合 1Panel 或原生 Docker），实现 7×24 后台常驻、崩溃自动拉起。

---

## 一、部署包里有什么

| 文件 | 作用 |
|---|---|
| `Dockerfile` | 构建应用镜像（Python 3.10 + 依赖） |
| `docker-compose.yml` | 一键编排：端口、数据卷、环境变量 |
| `docker-entrypoint.sh` | 容器启动脚本：迁移 → 静态文件 → 内置账号 → gunicorn |
| `.dockerignore` | 构建时排除数据库/备份/临时文件 |

数据全部落在两个挂载卷里，**重建容器、升级镜像都不会丢数据**：

- `./data/db.sqlite3` —— 数据库（业务数据全在这一个文件里）
- `./backup/` —— 自动备份目录

---

## 二、迁移数据（先做）

在 **Windows 电脑**上把数据库拷出来，传到 Linux 服务器的项目目录：

```
资产管理系统/
├── data/
│   └── db.sqlite3     ← 把 Windows 上的 db.sqlite3 拷成这个名字
└── （部署包文件）
```

> Windows 上的库文件位置：`C:\Users\Administrator\Desktop\资产管理系统\data\db.sqlite3`
>（本机工作区已与部署结构对齐，数据库统一放在 `data/` 目录下）
>
> ⚠️ 拷贝前先停掉 Windows 上的服务（关掉 cmd 窗口即可），避免拷到写到一半的文件。
> 传文件可用 scp / WinSCP / 1Panel 的文件管理器上传。

---

## 三、方式 A：用 1Panel 部署（推荐）

前提：服务器已装 1Panel（本文按 1Panel v1.x 界面描述，不同小版本入口名称可能略有差异）。

整个过程 6 步：**上传文件 → 改密钥 → 放行端口 → 创建编排 → 看日志确认启动 → 验证登录**。全程约 10 分钟（首次构建视网速）。

### 3.0 前置确认

在服务器终端（1Panel → 主机 → 终端）执行：

```bash
docker version        # 能出版本号即 Docker 正常（1Panel 会自带安装）
docker compose version
free -h && df -h /opt  # 确认内存 ≥ 1G、磁盘剩余 ≥ 2G
```

### 3.1 第一步：上传项目文件到服务器

**① 建目录**：1Panel → 文件 → 进入 `/` → 依次新建 `/opt/assets`。
> ⚠️ 路径务必**纯英文、层级浅**（推荐 `/opt/assets`）。中文路径或过深嵌套会让后面创建编排时报"路径读为目录"之类的错。

**② 打包上传**：在 Windows 上把项目文件夹压缩成 `assets.zip`，然后
1Panel → 文件 → 进入 `/opt/assets` → 右上角「上传」→ 选中 zip → 上传完成后右键 **解压**。
（也可用 WinSCP / `scp` 直传，效果相同。）

**③ 整理成最终结构**：解压后确认目录长这样——

```
/opt/assets/
├── Dockerfile
├── docker-compose.yml
├── docker-entrypoint.sh
├── .dockerignore
├── requirements.txt
├── manage.py
├── ensure_admin.py
├── assets/                  # 应用代码（含 migrations）
├── assets_system/           # Django 配置
├── templates/
├── static/
├── data/
│   └── db.sqlite3           ← 从 Windows 拷来的数据库（没有就建 data 目录，首次启动自动生成空库）
└── backup/                  # 自动备份落盘目录（可为空目录）
```

**④ 放数据库**：把 Windows 上的 `db.sqlite3` 上传到 `/opt/assets/data/db.sqlite3`。
> ⚠️ 拷贝前先停掉 Windows 上的服务（关掉 cmd 窗口），避免拷到写到一半的文件。
> 校验大小与 Windows 上一致：`ls -lh /opt/assets/data/db.sqlite3`。

**可以不传**（省空间，构建时会被 `.dockerignore` 自动排除，传了也不影响）：
`实际数据/`、`*.bat`、`archive/`、`db.demo.sqlite3`、`.git/`、`.workbuddy/`、`deploy/`、`README.md`。
> 注意：**`data/` 目录必须传**（里面是数据库），它只是不进镜像，作为宿主机挂载卷使用。

### 3.2 第二步：修改 docker-compose.yml（改密钥）

1Panel → 文件 → 打开 `/opt/assets/docker-compose.yml` → 编辑：

- `ASSETS_SECRET_KEY`：把 `please-change-me-to-a-long-random-string` 换成一串随机长字符串
  （1Panel → 工具箱 → 随机字符串 生成一个 32 位以上的，粘贴进去）
- `ASSETS_ALLOWED_HOSTS`：局域网用保持 `*` 即可；有固定 IP/域名可改成具体值（逗号分隔）
- `ports` 里 `"12036:8000"`：对外端口。想换端口只改冒号**前面**那个数字

> ⚠️ 只需要改 `environment` 段，**不要动** `volumes`、`depends_on`、`command` 等结构。

### 3.3 第三步：放行端口

1. 1Panel → 主机 → 防火墙 → 创建端口规则：放行 **12036/TCP**
2. 如果是云服务器（阿里云/腾讯云等），还要在**云控制台的安全组**里同样放行 12036/TCP——这一步最容易漏，表现就是"容器日志正常但浏览器打不开"

### 3.4 第四步：创建编排

1Panel → 容器 → **编排** → **创建编排**：

| 字段 | 填什么 |
|---|---|
| 名称 | `assets`（小写英文） |
| 来源 / 模板 | 选 **路径（本地目录 / path）** 方式，**不要**选"从模板编辑"里手写内容 |
| 路径 | `/opt/assets`（即 `docker-compose.yml` 所在目录） |

点「确认」开始创建。

> **两个高频踩坑，都在这一步：**
>
> - **提示"项目名不能为空"** → 不是上面的"名称"，而是编排表单里的**文件夹/目录**那一栏没选。用路径选择器选到 `/opt/assets` 这一**层**（选中目录本身，不是只停在 `/opt`）。
> - **报错"路径读成了目录/文件"** → 路径含中文或嵌套过深。把整个项目挪到 `/opt/assets` 纯英文路径后重来。

创建成功后，1Panel → 容器 列表里应出现两个容器：

- `asset-management`（应用，端口映射 `12036 → 8000`）
- `asset-redis`（缓存，**无对外端口**，属正常现象）

### 3.5 第五步：看日志确认启动成功

1Panel → 容器 → `asset-management` → **日志**。首次会先构建镜像（拉取 `python:3.10-slim`，约 1-2 分钟，慢的话可能 5-10 分钟）。

日志依次出现下面几行即启动完成：

```
[entrypoint] 应用数据库迁移...
[entrypoint] 收集静态文件...
[entrypoint] 确保内置管理员账号存在...
[entrypoint] 启动 gunicorn...
[INFO] Listening at: http://0.0.0.0:8000
```

> 日志卡住不动超过 10 分钟：回到日志开头找红字报错，对照 3.7 排查表。

### 3.6 第六步：验证

浏览器访问 `http://服务器IP:12036`：

1. 用 `admin / admin123` 登录
2. **立刻**右上角改密码（这是公网可访问的入口，必须做）
3. 按下表快速自检一遍：

| 检查项 | 预期 |
|---|---|
| 资产库列表 | 能看到从 Windows 带过来的资产行数 |
| 新增一条领用 | 资产状态变「借出」，责任人/实际使用人/部门同步变化 |
| 归还该领用 | 资产回「库存」，责任人/使用人=资产管理员、部门=综合管理部 |
| 数据备份 → 手动备份 | `./backup/` 下出现 `.sqlite3` 快照文件 |
| 手机浏览器打开 | 自动切换为移动端布局 |
| 故意输错密码 5 次 | 提示锁定 5 分钟（Redis 缓存已生效） |

### 3.7 常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 创建编排提示"项目名不能为空" | 编排表单的文件夹/目录栏未选择 | 用路径选择器选中 `/opt/assets` 目录本身 |
| 报错"路径读为目录/文件" | 中文路径或目录嵌套过深 | 整个项目移到 `/opt/assets` 纯英文路径 |
| 构建时拉镜像超时/很慢 | 服务器访问 Docker Hub 不稳 | 配置 Docker 镜像加速（1Panel → 容器 → 设置），或稍后重试 |
| 容器反复重启（Restarts 上涨） | 看 `asset-management` 日志末尾的红字 | 常见是 `db.sqlite3` 没放对位置或权限不对，确认在 `data/` 下 |
| 日志正常但浏览器打不开 | 端口没放行 | 检查 1Panel 防火墙 + 云安全组是否都放行 12036 |
| 打开是 502 / Bad Gateway | 应用容器还没起完，或挂了 | 等构建完成再看；仍不行看应用日志红字 |
| 日志报 `database is locked` | 多进程同时写 SQLite（少见） | 保持 `--workers 1` 默认配置即可，不要随意调大 workers |
| 登录提示"已被锁定" | 密码连错 5 次 | 等 5 分钟自动解锁，或 `docker exec asset-redis redis-cli del "login:lock:用户名"` |
| 页面样式错乱 | 静态文件未收集 | 确认日志里有 `collectstatic` 那一行；没有就重启容器 |

### 3.8 以后怎么更新代码 / 重建

**方式一（服务器上有 git 仓库）**：
```bash
cd /opt/assets
git pull
docker compose up -d --build
```

**方式二（1Panel 界面操作）**：把改动后的文件覆盖上传到 `/opt/assets` → 容器 → 编排 → 选中 `assets` → **重新构建/重启**。

> 数据都在 `./data` 和 `./backup` 两个挂载卷里，**重建容器、更新镜像都不会丢数据**。

### 3.9 绑定域名 + HTTPS（可选，用 1Panel 反向代理）

部署好之后想用 `http://资产.你的域名.com` 这样的主域名访问，不用改系统代码，在 1Panel 前面加一层反向代理即可。

**① 域名解析**

到域名服务商（阿里云/腾讯云/Cloudflare 等）加一条 **A 记录**：
- 主机记录：如 `assets`（即 `assets.example.com`）
- 记录值：这台服务器的公网 IP
- 生效需要几分钟到几小时不等，可用 `ping assets.example.com` 验证是否已指到服务器

**② 1Panel 创建反向代理网站**

1Panel → **网站** → **创建网站** → 选择 **反向代理**：
- 主域名：`assets.example.com`（填完整域名，不要带 `http://`）
- 代理地址：`http://127.0.0.1:12036`（本机端口，指向资产系统）
- 代理名称：随意，如 `assets`
- 点击确认创建

**③ 申请 HTTPS 证书（推荐）**

网站列表 → 选中刚建的站点 → **HTTPS** 标签：
- 选择 **Let's Encrypt / ACME 一键申请**（1Panel 会自动完成验证和续期）
- 申请成功后勾选 **强制 HTTPS**（http 访问自动跳 https）

**④ 修改容器的 CSRF 配置（关键，不做会 403）**

用域名（尤其 https）访问时，编辑 `/opt/assets/docker-compose.yml`，把：

```yaml
      - ASSETS_CSRF_ORIGINS=
```

改成（**必须带 https:// 前缀，不要带结尾斜杠**）：

```yaml
      - ASSETS_CSRF_ORIGINS=https://assets.example.com
```

然后重建：1Panel → 容器 → 编排 → `assets` → 重新构建/重启。
不填的话，能打开页面，但在域名下**点任何"提交/保存"按钮都会报 403 CSRF 错误**。

**⑤ 验证**

- 浏览器打开 `https://assets.example.com` → 显示登录页 ✅
- 输入 admin 密码登录 → 成功进入首页 ✅
- 随便做一次保存操作（如改个备注）→ 不报 403 ✅

> 提示：配了域名后，服务器上的 12036 端口可以不对外开放（1Panel 防火墙/安全组里关掉），只留 80/443，系统就只能通过域名访问，更安全。
> 域名下打不开？先确认安全组放行了 **80、443** 端口（见 3.3）。

## 四、方式 B：原生 Docker（不用面板）

```bash
cd /opt/assets
docker compose up -d --build      # 构建并启动
docker compose logs -f            # 看启动日志，出现 gunicorn 即成功
```

停止 / 重启 / 升级：

```bash
docker compose down               # 停止（数据保留在 ./data 和 ./backup）
docker compose up -d              # 启动
git pull && docker compose up -d --build   # 代码更新后重建
```

## 五、日常运维

| 操作 | 方法 |
|---|---|
| 看运行日志 | 1Panel 容器 → 日志；或 `docker compose logs -f` |
| 备份 | 系统内「数据备份」页照常可用，文件落在服务器 `./backup/` |
| 恢复备份 | 备份文件是整库快照，停容器 → 用它覆盖 `data/db.sqlite3` → 起容器 |
| 手机访问 | 同一局域网直接访问 `http://服务器IP:12036`；外网访问建议配域名 + HTTPS（1Panel 网站功能可反代） |
| 更新代码 | 服务器上 `git pull && docker compose up -d --build` |

## 六、缓存与 worker 说明

部署包默认带了一个 **Redis 容器**（`redis:7-alpine`，仅容器网络内部可访问，不对外开端口）：

- 「密码连错 5 次锁定 5 分钟」的计数与锁定状态存在 Redis 里，**重启应用容器不丢失、多进程共享**
- 应用通过环境变量 `ASSETS_REDIS_URL=redis://redis:6379/0` 自动启用；不设置该变量则回退到进程内存缓存
- 当前配置为单 worker + 4 线程，小团队完全够用。将来并发上去了，直接把 `docker-entrypoint.sh` 里的 `--workers 1` 调大即可，锁定逻辑无需任何改动（Redis 已就位）

## 七、与 Windows 版的差异

- 不再需要 `start.bat`，没有 cmd 窗口，也不存在 QuickEdit 冻结问题
- DEBUG 默认关闭，静态文件由 WhiteNoise 提供（已内置，无需配置）
- 服务随容器常驻：崩溃、宿主机重启都会自动恢复（`restart: always`）
