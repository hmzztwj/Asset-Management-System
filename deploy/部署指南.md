## 一、部署包与数据说明

### 1.1 部署包里有什么

| 文件 | 作用 |
|---|---|
| `Dockerfile` | 构建应用镜像（Python 3.10 + 依赖） |
| `docker-compose.yml` | 一键编排：端口、数据卷、环境变量 |
| `docker-entrypoint.sh` | 容器启动脚本：迁移 → 静态文件 → 内置账号 → gunicorn |
| `.dockerignore` | 构建时排除数据库/备份/临时文件 |

### 1.2 什么在容器外、什么在容器里 ⭐

**这是全文最关键的一条认知** —— 它决定了「改完东西要不要重建镜像」：

| 内容 | 存放位置 | 改完怎么生效 |
|---|---|---|
| 数据库、附件、日志 | 宿主机 `./data`（**挂载卷**） | 立即生效，无需任何操作 |
| 自动备份 | 宿主机 `./backup`（**挂载卷**） | 立即生效 |
| 代码、模板、静态文件 | **镜像内部** `/app/...` | 必须**重建镜像**（见第五章） |

`docker-compose.yml` 只挂了这两个目录：

```yaml
volumes:
  - ./data:/app/data     # 数据库 + 附件 + 日志
  - ./backup:/app/backup # 备份
```

代码则是 Dockerfile 里 `COPY . .` 在**构建镜像那一刻**打进镜像的。所以：

- 把新文件上传到 `/opt/assets/`，只改了宿主机磁盘，**运行中的容器读不到**；
- `docker compose up -d` 和 1Panel 的「重启」都**不会重建镜像**，Docker 会直接复用旧镜像。

> 好消息：数据全在两个挂载卷里，**重建容器、更新镜像都不会丢数据**。

### 1.3 环境变量速查

都在 `docker-compose.yml` 的 `environment` 段。改完需要重建容器（见 5.1）：

| 变量 | 默认值 | 作用 / 什么时候要改 |
|---|---|---|
| `ASSETS_SECRET_KEY` | `please-change-me-...` | **部署必改**：换成一串随机长字符串 |
| `ASSETS_ALLOWED_HOSTS` | `*` | 放行哪些 Host。保持 `*` 最省事；一旦收紧成具体值，**必须把访问用的名字全列上**（IP + 带 www 域名 + 裸域名），漏一个就 400（见 4.2 第 ④ 步） |
| `ASSETS_CSRF_ORIGINS` | 空 | **只有「域名 + HTTPS」场景需要**，如 `https://assets.example.com`。不填则域名下点任何保存按钮报 403（见 4.3） |
| `ASSETS_REDIS_URL` | `redis://redis:6379/0` | 登录锁定计数存哪。留默认即用自带 Redis 容器；清空则退回进程内存（见 6.2） |
| `ASSETS_PUBLIC_BASE_URL` | 空 | **二维码里写哪个地址**。留空 = 跟着「打印标签时的访问地址」走：用 `127.0.0.1` 打开本页再打印，扫码就会指向 `127.0.0.1`、手机打不开。**建议固定**成手机能访问的地址，如 `http://10.10.2.7:12036` 或 `http://www.mdassetsmg.com`（见第九章第 2 条） |
| `ASSETS_DB_PATH` | `data/db.sqlite3` | 数据库位置，一般不用改 |
| `ports` | `"12036:8000"` | 对外端口。改端口只动冒号**前面**的数字；也可加内网 IP 前缀限制来源（见 4.1） |

## 二、部署前准备

### 2.1 前置检查

在服务器终端执行（1Panel → 主机 → 终端）：

```bash
docker version          # 能出版本号即 Docker 正常（1Panel 会自带安装）
docker compose version
free -h && df -h /opt   # 确认内存 ≥ 1G、磁盘剩余 ≥ 2G
```

### 2.2 迁移数据（从 Windows 带库文件）

在 **Windows 电脑**上把数据库传上去。

> 本机的库文件位置：`C:\Users\Administrator\Desktop\资产管理系统\assetsmg\data\db.sqlite3`
>（工作区已与部署结构对齐，数据库统一放在 `data/` 目录下）

上传目标：`/opt/assets/data/db.sqlite3`

```
/opt/assets/
├── data/
│   └── db.sqlite3     ← 从 Windows 拷来的数据库
└── （部署包文件）
```

- ⚠️ 拷贝前先**停掉 Windows 上的服务**（关掉 cmd 窗口即可），避免拷到写到一半的文件。
- 传完校验大小一致：`ls -lh /opt/assets/data/db.sqlite3`
- 传文件可用 scp / WinSCP / 1Panel 文件管理器上传。
- 没有库文件也行：不建 `data/` 目录，首次启动会自动生成空库。

## 三、部署步骤（方式 A：1Panel，六步）

前提：服务器已装 1Panel（本文按 1Panel v1.x 界面描述，不同小版本入口名称可能略有差异）。

流程：**上传文件 → 改密钥 → 放行端口 → 创建编排 → 看日志 → 验证登录**，约 10 分钟（首次构建视网速）。

> 不用 1Panel、想走纯 Docker 命令的，直接看 **第八章**。

### 3.1 第一步：上传项目文件到服务器

**① 建目录**：1Panel → 文件 → 进入 `/` → 新建 `/opt/assets`。
> ⚠️ 路径务必**纯英文、层级浅**（推荐 `/opt/assets`）。中文路径或过深嵌套会让后面创建编排时报"路径读为目录"之类的错。

**② 打包上传**：在 Windows 上把项目文件夹压缩成 `assets.zip`，1Panel → 文件 → 进入 `/opt/assets` → 右上角「上传」→ 上传完成后右键 **解压**。
（也可用 WinSCP / `scp` 直传，效果相同。）

**③ 整理成最终结构**：解压后确认目录长这样——

```
/opt/assets/
├── Dockerfile
├── docker-compose.yml
├── docker-entrypoint.sh
├── .dockerignore
├── requirements.txt
├── manage.py
├── ensure_admin.py
├── assets/                  # 应用代码（含 migrations）
├── assets_system/           # Django 配置
├── templates/
├── static/
├── data/
│   └── db.sqlite3           ← 从 Windows 拷来的数据库（见 2.2；没有就建 data 目录，首次启动自动生成空库）
└── backup/                  # 自动备份落盘目录（可为空目录）
```

**④ 可以不传**（省空间，构建时会被 `.dockerignore` 自动排除，传了也不影响）：
`实际数据/`、`*.bat`、`archive/`、`db.demo.sqlite3`、`.git/`、`.workbuddy/`、`deploy/`、`README.md`。

> 注意：**`data/` 目录必须传**（里面是数据库）。它只是不进镜像，作为宿主机挂载卷使用。

### 3.2 第二步：修改 docker-compose.yml（改密钥）

1Panel → 文件 → 打开 `/opt/assets/docker-compose.yml` → 编辑：

- `ASSETS_SECRET_KEY`：把 `please-change-me-to-a-long-random-string` 换成一串随机长字符串
  （1Panel → 工具箱 → 随机字符串 生成一个 32 位以上的，粘贴进去）
- `ASSETS_ALLOWED_HOSTS`：局域网用保持 `*` 即可；要收紧请先读 **1.3** 和 **4.2 第 ④ 步**
- `ports` 里 `"12036:8000"`：对外端口。想换端口只改冒号**前面**那个数字

> ⚠️ 只改 `environment` 段，**不要动** `volumes`、`depends_on`、`command` 等结构。
> 各变量完整说明见 **1.3 环境变量速查**。

### 3.3 第三步：放行端口

1. 1Panel → 主机 → 防火墙 → 创建端口规则：放行 **12036/TCP**
2. 如果是云服务器（阿里云/腾讯云等），还要在**云控制台的安全组**里同样放行 12036/TCP —— 这一步最容易漏，表现就是"容器日志正常但浏览器打不开"

> 之后若要加域名访问，还得放行 80（见 4.2）/ 443（见 4.3）。

### 3.4 第四步：创建编排

1Panel → 容器 → **编排** → **创建编排**：

| 字段 | 填什么 |
|---|---|
| 名称 | `assets`（小写英文） |
| 来源 / 模板 | 选 **路径（本地目录 / path）** 方式，**不要**选"从模板编辑"里手写内容 |
| 路径 | `/opt/assets`（即 `docker-compose.yml` 所在目录） |

点「确认」开始创建。

> **两个高频踩坑，都在这一步：**
>
> - **提示"项目名不能为空"** → 不是上面的"名称"，而是编排表单里的**文件夹/目录**那一栏没选。用路径选择器选到 `/opt/assets` 这一**层**（选中目录本身，不是只停在 `/opt`）。
> - **报错"路径读成了目录/文件"** → 路径含中文或嵌套过深。把整个项目挪到 `/opt/assets` 纯英文路径后重来。

创建成功后，1Panel → 容器 列表里应出现两个容器：

- `asset-management`（应用，端口映射 `12036 → 8000`）
- `asset-redis`（缓存，**无对外端口**，属正常现象）

### 3.5 第五步：看日志确认启动成功

1Panel → 容器 → `asset-management` → **日志**。首次会先构建镜像（拉取 `python:3.10-slim`，约 1-2 分钟，慢的话可能 5-10 分钟）。

日志依次出现下面几行即启动完成：

```
[entrypoint] 应用数据库迁移...
[entrypoint] 收集静态文件...
[entrypoint] 确保内置管理员账号存在...
[entrypoint] 启动 gunicorn...
[INFO] Listening at: http://0.0.0.0:8000
```

> 日志卡住不动超过 10 分钟：回到日志开头找红字报错，对照 **第七章**。

### 3.6 第六步：验证

浏览器访问 `http://服务器IP:12036`：

1. 用 `admin / admin123` 登录
2. **立刻**右上角改密码（这是可被访问的入口，必须做）
3. 按下表快速自检一遍：

| 检查项 | 预期 |
|---|---|
| 资产库列表 | 能看到从 Windows 带过来的资产行数 |
| 新增一条领用 | 资产状态变「借出」，责任人/实际使用人/部门同步变化 |
| 归还该领用 | 资产回「库存」，责任人/使用人=资产管理员、部门=综合管理部 |
| 数据备份 → 手动备份 | `./backup/` 下出现 `.sqlite3` 快照文件 |
| 手机浏览器打开 | 自动切换为移动端布局 |
| 故意输错密码 5 次 | 提示锁定 5 分钟（Redis 缓存已生效） |

到这一步系统已经能用（IP + 端口）。**如果只在内网使用，其实就可以收工了** —— 建议顺手把端口限制到内网 IP，防止意外暴露到公网（见 4.1）。

## 四、访问方式（三选一）

系统本身不关心你怎么访问它，选哪种只影响**前面的入口怎么搭**。三种可以叠加（比如内网域名 + 公网 HTTPS 同时用），但**先把 IP + 端口这条底线跑通**，它是排障时最好的对照物。

| 场景 | 访问地址长这样 | 需要做什么 | 适合 |
|---|---|---|---|
| **A 内网 IP + 端口** | `http://10.10.2.7:12036` | 第三章做完即可用；再加一步限制来源 | 只给公司内部用，最省事 |
| **B 内网主域名** ✅ 本项目采用 | `http://www.mdassetsmg.com` | 防火墙静态 DNS + 1Panel 反代 80 | 想用域名，但不希望暴露到公网 |
| **C 公网域名 + HTTPS** | `https://assets.example.com` | 公网 A 记录 + 反代 + 证书 + CSRF 配置 | 需要在外网访问 |

### 4.1 场景 A：只在内网使用（推荐，最省事）

如果这个系统只给公司内部同事用、不需要外网访问，那 **不用买域名、不用配 HTTPS、不用做反向代理**。

**① 访问方式：直接用内网 IP + 端口**

```
http://192.168.1.10:12036        ← 把 192.168.1.10 换成服务器的内网 IP
```

不知道服务器内网 IP？服务器上执行 `ip addr`（找 `192.168.x.x` 或 `10.x.x.x` 那个）或 `hostname -I`。

**② 三个能让同事更好记的替代方案（可选）**

| 方案 | 做法 | 适用 |
|---|---|---|
| 内网 DNS 映射 | 在路由器（如爱快/OpenWrt）或内网 DNS 服务器里加一条：`assets.公司内网` → 服务器内网 IP | 全公司同事都能用域名访问，最省事 |
| 改本地 hosts | 每台电脑改 `C:\Windows\System32\drivers\etc\hosts`，加一行 `192.168.1.10  assets.内网` | 只给少数几台机器用，不用动路由器 |
| 直接发 IP | 把 `http://192.168.1.10:12036` 存成浏览器书签 | 最简单，零配置 |

> 注意：这种方式下域名只是"内部别名"，**不解析到公网、也没有证书**，所以用 `http://` 而不是 `https://`，浏览器可能提示"不安全"，内网自用点继续即可。

**③ 确保外网访问不到（关键）**

内网自用最怕的是"顺手把端口暴露到公网"。三层保险，**至少做第一层**：

1. **容器端口只绑内网 IP**（最有效）
   编辑 `/opt/assets/docker-compose.yml`，把：

   ```yaml
   ports:
     - "12036:8000"
   ```

   改成（`192.168.1.10` 换成服务器内网 IP）：

   ```yaml
   ports:
     - "192.168.1.10:12036:8000"
   ```

   改完重建：1Panel → 容器 → 编排 → `assets` → 重新构建。
   这样即使防火墙放行了 12036，外网也连不上，**只有内网能访问**。

2. **云服务器安全组**：如果服务器是云主机，把 12036 的入站规则删掉，或来源只填公司出口 IP / 内网网段（如 `192.168.0.0/16`）。
3. **1Panel 防火墙**：把 12036 规则删除或限制来源 IP 段。

> 排查小技巧：在**公司内网**访问正常、用**手机 4G/5G**（外网）访问打不开 → 说明隔离成功 ✅
> 如果 4G 也能打开，说明端口还暴露着，回去做上面第 1、2 步。

**④ 不需要做的事**

- ❌ 不用改 `ASSETS_CSRF_ORIGINS`（那是域名 + HTTPS 场景才需要）
- ❌ 不用申请 SSL 证书
- ❌ 不用开放 80 / 443 端口
- ✅ `ASSETS_ALLOWED_HOSTS=*` 保持默认即可（内网 IP 访问本就允许）

### 4.2 场景 B：内网主域名双入口（IP+端口 与 主域名 并存）✅ 已实测

需求：内网里既能用 `http://10.10.2.7:12036` 访问，也能用 `http://www.mdassetsmg.com` 访问（不用记 IP 和端口），且**外网访问不到**。

思路：域名只在**内网解析**到服务器内网 IP，再由 1Panel 的反代把 80 端口转给资产系统；IP+端口这条老路完全不动，两条并行。

```
内网电脑 ─┬─ http://10.10.2.7:12036 ──────────────► Docker 端口映射 :12036 ┐
          │                                                                 ├─► 资产系统(:8000)
          └─ http://www.mdassetsmg.com ─► 防火墙静态DNS(→10.10.2.7)
                                          └► 1Panel 反代 :80 ─────────────┘
```

**① 在防火墙上加静态 DNS（以奇安信网神为例）**

入口（按版本二选一）：
- **SecGate 3600（v3.x）**：网络配置 → **DNS → 静态 DNS**
- **奇安信下一代防火墙（NBM）**：网络配置 → **域名解析配置 → DNS 代理静态域名解析**

新建一条，填「域名 → IP」，例如：

| 名称 | 匹配模式 | 入接口 | 域名 | IP |
|---|---|---|---|---|
| 资产管理系统域名解析 | 入接口 | vlan2 | `www.mdassetsmg.com` | `10.10.2.7` |
| （建议再加一条） | 入接口 | vlan2 | `mdassetsmg.com` | `10.10.2.7` |

注意事项：
- **一个域名一条记录**，带 www 和不带 www 是**两个域名**，都要加（否则裸域名打不开）
- `匹配模式=入接口` 要选**用户实际所在的接口/VLAN**；多个 VLAN 的用户都要访问，就给每个接口各建一条（或改用「源地址」模式）
- **部署模式必须是网关/网桥** —— 官方文档明确：DNS 代理静态域名解析**镜像模式不支持**
- 别配到「系统 DNS 服务器 / 主备 DNS」那一项 —— 那是防火墙自己上网解析（升级特征库、URL 过滤）用的，跟内网客户端域名映射不是一回事
- 服务器的 IP 要固定（DHCP 里做 IP-MAC 绑定或设静态），否则 IP 一变域名就指错机器

**② 防火墙放行 80 端口**

域名访问走 80（不带端口）。安全策略里加一条：源=内网网段 → 目的=`10.10.2.7` → 服务=`HTTP(80)` → 允许。
同时 1Panel 的防火墙也要放行 80。

**③ 1Panel 创建反向代理网站**

网站 → 创建网站 → **反向代理**：
- 主域名：`www.mdassetsmg.com`
- **代理地址：`http://127.0.0.1:12036`**（注意是 `http://`，不是 https）
- 想让裸域名也能访问，就在该站点的**域名**设置里再加 `mdassetsmg.com`

**④ 如果收紧了 ASSETS_ALLOWED_HOSTS，把访问用的名字全列上（本次踩坑点）**

`docker-compose.yml` 里默认是 `- ASSETS_ALLOWED_HOSTS=*`，此时任何域名都能访问、无需改动。
一旦收紧成具体值，就**必须把三种访问方式都写进去**，漏一个对应方式就报错：

```yaml
      - ASSETS_ALLOWED_HOSTS=10.10.2.7,www.mdassetsmg.com,mdassetsmg.com
```

> 实测教训：只写了部分主机名时，用域名访问会直接返回一页素面的
> **`Bad Request (400)`** —— 这是 Django 的 ALLOWED_HOSTS 拒绝（不是防火墙、不是 DNS 问题）。
> 症状很好认：`tracert`/`ping` 域名能通、端口也通，但页面是 400。
> 改完执行「重建编排」才生效。

**⑤ 验证（三步都绿才算成功）**

在内网电脑上：

```bash
ipconfig /flushdns
nslookup www.mdassetsmg.com     # 应返回 10.10.2.7，而不是公网地址
```

- `http://10.10.2.7:12036` → 登录页 ✅（老入口不受影响）
- `http://www.mdassetsmg.com` → 登录页 ✅
- 用手机 4G/5G 访问域名 → 打不开 ✅（说明只在内网生效）
- 两边各登录一次、各保存一个操作 → 数据一致 ✅

> 内网 http 场景**不需要** `ASSETS_CSRF_ORIGINS`（Django 只对 https 请求做 Origin 校验），保持默认即可。
> 打不开的各种情况，对照 **第七章 7.3**。

### 4.3 场景 C：公网域名 + HTTPS（可选）

想在**外网**用 `https://assets.example.com` 访问时用这套。不用改系统代码，在 1Panel 前面加一层反向代理即可。

**① 域名解析**

到域名服务商（阿里云/腾讯云/Cloudflare 等）加一条 **A 记录**：
- 主机记录：如 `assets`（即 `assets.example.com`）
- 记录值：这台服务器的**公网 IP**
- 生效需要几分钟到几小时不等，可用 `ping assets.example.com` 验证是否已指到服务器

**② 1Panel 创建反向代理网站**

1Panel → **网站** → **创建网站** → 选择 **反向代理**：
- 主域名：`assets.example.com`（填完整域名，不要带 `http://`）
- 代理地址：`http://127.0.0.1:12036`（本机端口，指向资产系统）
- 代理名称：随意，如 `assets`
- 点击确认创建

**③ 申请 HTTPS 证书（推荐）**

网站列表 → 选中刚建的站点 → **HTTPS** 标签：
- 选择 **Let's Encrypt / ACME 一键申请**（1Panel 会自动完成验证和续期）
- 申请成功后勾选 **强制 HTTPS**（http 访问自动跳 https）

**④ 修改容器的 CSRF 配置（关键，不做会 403）**

用域名（尤其 https）访问时，编辑 `/opt/assets/docker-compose.yml`，把：

```yaml
      - ASSETS_CSRF_ORIGINS=
```

改成（**必须带 https:// 前缀，不要带结尾斜杠**）：

```yaml
      - ASSETS_CSRF_ORIGINS=https://assets.example.com
```

然后重建：1Panel → 容器 → 编排 → `assets` → 重新构建。

> 不填的话，能打开页面，但在域名下**点任何"提交/保存"按钮都会报 403 CSRF 错误**。

**⑤ 验证**

- 浏览器打开 `https://assets.example.com` → 显示登录页 ✅
- 输入 admin 密码登录 → 成功进入首页 ✅
- 随便做一次保存操作（如改个备注）→ 不报 403 ✅

> 提示：配了域名后，服务器上的 12036 端口可以不对外开放（1Panel 防火墙/安全组里关掉），只留 80/443，系统就只能通过域名访问，更安全。
> 域名下打不开？先确认安全组放行了 **80、443** 端口（见 3.3）。

## 五、更新代码与重建（高频操作）

### 5.1 标准流程

**方式一（服务器上有 git 仓库）**：

```bash
cd /opt/assets
git pull
docker compose up -d --build
```

**方式二（1Panel 界面操作）**：把改动后的文件覆盖上传到 `/opt/assets` → 容器 → **编排** → 选中 `assets` → **重新构建**（个别版本叫「重新部署」，是同一个动作）。

> ⚠️ **必须走「重新构建」（`--build`），不能只点「重启」** —— 原因见 5.2。

只有两类改动**不需要** `--build`：

1. `./data` 里的数据库 / 附件（挂载卷，容器内直接可见）；
2. `docker-compose.yml` 的 `environment` 段（`docker compose up -d` 会重建容器即生效）。

其余任何代码、模板、静态文件改动，都必须 `--build`。

### 5.2 为什么「重启」不管用 ⭐

**因为代码不在挂载卷里，而在镜像里**（见 1.2）。`templates/`、`static/`、`assets/` 都是 Dockerfile 里 `COPY . .` 在**构建那一刻**打进镜像的：

- 新文件传到宿主机 `/opt/assets/` → 只改了宿主机磁盘；
- 容器里的 `/app/...` → 仍是上次构建时的副本；
- 「重启」和不带 `--build` 的 `docker compose up -d` → Docker 发现 `asset-management:latest` 已存在，**直接复用旧镜像**，页面自然还是旧的。

### 5.3 怎么确认服务器跑的是新代码

**① 不用登服务器（最快，任意内网电脑即可）**

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://服务器IP:12036/a/
# 200 = 新版（含扫码快照页）   404 = 旧版（该路由还不存在）

curl -s http://服务器IP:12036/static/css/style.css | grep -c "modal-mask"
# 1 = 新版（逾期弹窗样式）     0 = 旧版
```

**② 在服务器上（能登进去时，更直接）**

```bash
docker images asset-management:latest                       # 构建时间早于上传时间 = 没重建
docker exec asset-management md5sum /app/templates/dashboard.html
md5sum /opt/assets/templates/dashboard.html                  # 两个 md5 不同 → 就是这个原因

# 或直接看新版特征标记（新版应为 6 / 4，返回 0 就是旧代码）
docker exec asset-management grep -c syncCharts  /app/templates/dashboard.html
docker exec asset-management grep -c overdue-modal /app/templates/base.html
```

> 重建完成后浏览器记得 **Ctrl+F5 强刷**一次（反代或浏览器可能还缓存着旧的 CSS/JS）。

### 5.4 三个常见误区

**① 别用容器列表里的「升级」按钮更新代码**

「升级」的含义是**从镜像仓库（Docker Hub）拉一个新镜像来替换**（如 redis 出了新版本）。而 `asset-management:latest` 是本机构建的镜像，仓库里不存在 —— 点「确认」后 Docker 会去 `registry-1.docker.io` 找它，结果要么报 `pull image ... failed`（服务器连不上 Docker Hub，`context deadline exceeded`），要么报 `manifest unknown`。

> **更新自己的代码永远走「编排 → 重新构建」或终端 `docker compose up -d --build`。**

**② 别在「容器 → 终端」里执行 docker 命令**

`docker compose` 是**管理容器**的命令，必须在**宿主机终端**执行（1Panel → **主机** → 终端，或 SSH 连服务器）。

在 1Panel「容器 → 终端」里执行会报 `docker: not found` —— 那是**容器内部**，只有 Python 和应用代码（`ls` 出来的就是 `/app`），没有 Docker CLI。相当于"站在冰箱里修冰箱"。

**③ 服务器连不上 Docker Hub，不影响重建**

基础镜像 `python:3.10-slim` 首次构建时已存在本地，`requirements.txt` 未变时 `pip install` 层命中缓存，重建实际只重跑 `COPY . .`（纯本地操作）。

> 若构建日志报基础镜像拉取失败，说明本地缓存被清过，先到 1Panel → 容器 → 设置 配置镜像加速再构建。

## 六、日常运维

### 6.1 常用操作

| 操作 | 方法 |
|---|---|
| 看运行日志 | 1Panel 容器 → 日志；或 `docker compose logs -f` |
| 备份 | 系统内「数据备份」页照常可用，文件落在服务器 `./backup/` |
| 恢复备份 | 备份文件是整库快照：停容器 → 用它覆盖 `data/db.sqlite3` → 起容器 |
| 更新代码 | 见 **第五章** |
| 手机访问 | 同一局域网直接访问 `http://服务器IP:12036`；外网访问见 4.3 |

### 6.2 缓存与 worker

部署包默认带了一个 **Redis 容器**（`redis:7-alpine`，仅容器网络内部可访问，不对外开端口）：

- 「密码连错 5 次锁定 5 分钟」的计数与锁定状态存在 Redis 里，**重启应用容器不丢失、多进程共享**
- 应用通过环境变量 `ASSETS_REDIS_URL=redis://redis:6379/0` 自动启用；不设置该变量则回退到进程内存缓存
- 当前配置为 **单 worker + 4 线程**，小团队完全够用。将来并发上去了，直接把 `docker-entrypoint.sh` 里的 `--workers 1` 调大即可，锁定逻辑无需任何改动（Redis 已就位）

> 为什么默认单 worker：SQLite 是单文件库，多进程同时写会出现 `database is locked`。保持默认即可，不要随意调大。

## 七、问题排查总表

### 7.1 部署阶段

| 现象 | 原因 | 处理 |
|---|---|---|
| 创建编排提示"项目名不能为空" | 编排表单的文件夹/目录栏未选择 | 用路径选择器选中 `/opt/assets` 目录本身 |
| 报错"路径读为目录/文件" | 中文路径或目录嵌套过深 | 整个项目移到 `/opt/assets` 纯英文路径 |
| 构建时拉镜像超时/很慢 | 服务器访问 Docker Hub 不稳 | 配置 Docker 镜像加速（1Panel → 容器 → 设置），或稍后重试 |
| 容器反复重启（Restarts 上涨） | 看 `asset-management` 日志末尾的红字 | 常见是 `db.sqlite3` 没放对位置或权限不对，确认在 `data/` 下 |
| 日志正常但浏览器打不开 | 端口没放行 | 检查 1Panel 防火墙 + 云安全组是否都放行 12036 |
| 打开是 502 / Bad Gateway | 应用容器还没起完，或挂了 | 等构建完成再看；仍不行看应用日志红字 |
| 日志报 `database is locked` | 多进程同时写 SQLite（少见） | 保持 `--workers 1` 默认配置即可，不要随意调大 |
| 登录提示"已被锁定" | 密码连错 5 次 | 等 5 分钟自动解锁，或 `docker exec asset-redis redis-cli del "login:lock:用户名"` |
| 页面样式错乱 | 静态文件未收集 | 确认日志里有 `collectstatic` 那一行；没有就重启容器 |

### 7.2 更新代码之后

| 现象 | 原因 | 处理 |
|---|---|---|
| **页面还是旧版本**（文件已上传、界面没变） | 只重启没重建镜像（代码在镜像里，不在挂载卷） | 见 **5.1**，执行 `docker compose up -d --build` |
| 容器「升级」报 `pull image ... failed` / `context deadline exceeded` | 误用「升级」入口去仓库拉本地构建的镜像 | 点取消；改正做法见 **5.4 ①** |
| 在容器终端执行报 `docker: not found` | 开的是容器内部终端 | 换宿主机终端，见 **5.4 ②** |
| 重建后样式仍不对 | 浏览器 / 反代缓存 | Ctrl+F5 强刷，或清反代缓存 |

### 7.3 域名访问（场景 B / C）

| 现象 | 原因 | 处理 |
|---|---|---|
| 素面 `Bad Request (400)` | Django ALLOWED_HOSTS 没包含该域名 | 见 **4.2 第 ④ 步**，改完重建 |
| 1Panel 默认页 / 404 | 请求域名与站点主域名不匹配（如访问裸域但只建了 www） | 把裸域名也加到站点域名里 |
| 域名解析出来是公网 IP | 客户端没走防火墙 DNS（被设成了 114/8.8.8.8），或浏览器开了安全 DNS(DoH) | 改回防火墙 DNS，关掉 DoH |
| 域名解析对了但打不开 | 80 端口没放行（防火墙 / 1Panel 两处） | 各放行一条 80 规则 |
| 提示"不安全" | 内网 http 无证书，正常现象 | 可忽略；要消除就得配 HTTPS（见 4.3） |
| 页面能开，但点保存报 **403** | 用了域名/HTTPS 却没配 CSRF | 见 **4.3 第 ④ 步** |

### 7.4 手机扫码打不开（本系统最常见）

| 现象 | 原因 | 处理 |
|---|---|---|
| 手机提示"无法访问此网站 / 找不到服务器" | 二维码里写的是 `127.0.0.1`（打印标签时用本机地址打开的页面） | 配 `ASSETS_PUBLIC_BASE_URL` 固定地址并重建，**然后重新打印标签**（见 9 第 2 条） |
| 同上，但地址看着没问题 | 手机不在该内网 / 没连同一 WiFi（内网 IP 场景必连内网） | 手机连上同一内网；或用域名并确保手机能解析（见 4.2） |
| 扫码打开是 400 | `ASSETS_ALLOWED_HOSTS` 没收全扫码用的域名 | 见 **4.2 第 ④ 步** |
| 扫码能看到信息卡，但信息是旧的 | 标签是资产变更前打印的快照 | 正常设计，重新打印该资产标签 |
| 扫出来是一串乱码/纯编号 | 标签是旧版本（快照模式上线前）打的 | 重新打印 |

## 九、扫码信息卡与标签打印（部署侧注意事项）

系统中的资产二维码**自带该资产的信息快照**，扫码打开的是免登录只读页 `/a/`（内容全部来自二维码，不查数据库）。部署时注意 4 件事：

1. **`/a/` 不要加额外鉴权**
   1Panel 站点若开了「Basic Auth / 访问密码」之类的访问限制，扫码页会一起被拦下，手机扫码就变成 401 弹框。扫码页本身已做限制（只读、无操作入口、`noindex`），无需再加一层。

2. **二维码里写哪个地址由 `ASSETS_PUBLIC_BASE_URL` 决定（务必固定）**
   二维码编码的是「扫码落地页地址 + 快照」，落地页地址按下面顺序取：
   - 配了 `ASSETS_PUBLIC_BASE_URL` → **一律用它**（推荐）；
   - 没配 → 取「打印标签时的访问地址」。

   所以留空时：用 `http://127.0.0.1:12036` 打开标签页再打印，标签上就印着 `127.0.0.1`，**手机扫码必然打不开**（这是最常见的踩坑）。做法二选一：
   - **推荐**：在 `docker-compose.yml` 里固定，例 `- ASSETS_PUBLIC_BASE_URL=http://www.mdassetsmg.com`（或内网 IP `http://10.10.2.7:12036`）；
   - 或每次都用主域名（`http://www.mdassetsmg.com/library/labels/`）打开标签页再打印，别用 IP/`127.0.0.1`。

   标签页顶部会实时显示「二维码指向哪个地址」：指向 `127.0.0.1`/`localhost` 时给黄条告警。

   注意：以后换服务器 IP、改端口或换域名，**已打印的旧标签会扫不通**，需要重新打印。

   | 扫码现象 | 原因 |
   |---|---|
   | 手机浏览器提示"无法访问此网站" | 二维码里的地址手机到不了（是 `127.0.0.1`，或手机不在同一内网/未连 WiFi） |
   | 手机能开、但显示的信息是旧的 | 标签是资产变更**之前**打印的，重新打印即可（快照设计） |
   | 提示 400 Bad Request | `ASSETS_ALLOWED_HOSTS` 收紧后没把扫码用的域名列进去（见 4.2 第 ④ 步） |

3. **标签上的信息是"打印那一刻"的快照**
   资产改名、换责任人、状态从「借出」变「库存」之后，旧标签仍显示旧信息 —— 这是刻意设计（便于与当时的台账核对），**信息变更后请重新打印该资产标签**。卡片页会标出快照时间，方便判断新旧。

4. **打印分辨率**
   二维码里带了信息，模块比纯编号密（约 69×69 模块）。打印时：
   - 打印机分辨率 ≥ 300dpi；
   - 浏览器打印对话框里勾选「背景图形 / Background graphics」，否则二维码不显示；
   - 标签上的二维码按 28mm 打印，**不要压缩纸张比例**，否则模块太小会扫不动。

> 二维码目前**只有"内嵌快照"这一种模式**（本项目明确要求，不再提供纯编号/纯文本模式）：扫码打开免登录只读信息卡，信息跟着二维码走，所以**手机只要能访问到 `ASSETS_PUBLIC_BASE_URL` 那个地址就行**（内网需要连同一 WiFi/内网，公网域名需能解析）。若日后希望扫码永远显示最新状态（而不是快照），需要把二维码改成短链模式并**重新打印全部标签**。

## 十、与 Windows 版的差异

- 不再需要 `start.bat`，没有 cmd 窗口，也不存在 QuickEdit 冻结问题
- DEBUG 默认关闭，静态文件由 WhiteNoise 提供（已内置，无需配置）
- 服务随容器常驻：崩溃、宿主机重启都会自动恢复（`restart: always`）
